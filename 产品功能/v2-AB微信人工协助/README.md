# v2 · AB微信人工协助

继承 [v1基础工作台](../v1-基础工作台/) 的功能，本版说明新增的实际代码。它不是软件Release标签；早先预览ZIP不一定包含本功能。

## 账号关系

- **A：销售私人微信**，由销售本人回答问题。
- **B：对客个人微信**，客户添加B，由系统辅助接待。
- 系统接入B，A正常使用微信，无需第三个助手微信号。

## 新增功能

| 功能 | 当前实现 |
|---|---|
| 配置入口 | 自动回复页面新增“A/B微信人工协助”，填写A准确会话标识并启用或停用 |
| 自动通知 | 启用后新产生的转人工问题，B向A发送客户称呼、部分问题摘要和唯一编号 |
| 人工解答 | A在与B的聊天框发送普通文字：`#完整问题编号 答案` |
| 精确匹配 | 校验A身份、原任务、客户和问题状态，不按最近问题猜测 |
| 回传客户 | 复用既有单次人工发送接口，由B发送给原客户并观察回执 |
| 状态记录 | 查看等待销售回答、等待发送、已发送、失败、未知和需复核等状态 |
| 防重复与恢复 | 发送意图先持久化，重复扫描不重发；中断或结果未知保留人工核对 |
| 防循环 | A排除在新客户自动接纳之外，并禁止作为客户档案参与接待 |
| 人工保护 | 转交后保护会话，新消息等影响旧答案时转复核，恢复托管沿用既有保护 |

## 实际使用流程

1. Windows电脑登录B，运行最新本地源码，准备并启用原生发送组件。
2. 确保A与B是好友，在自动回复页填写A的wxid等准确会话标识，启用人工协助。
3. 保存接待规则并启动，客户向B咨询。
4. 遇到需要人工的问题，B将编号及问题发送给A。
5. 销售用A发送 `#完整问题编号 答案`，系统核对后由B回传原客户。
6. 在页面查看处理状态；异常在原人工接管界面核查。

## 当前限制与验证

- 默认关闭，只处理启用之后新产生的转人工问题，不补发历史队列。
- 使用普通文字摘要与明确编号；**未实现原生转发卡片及引用卡片解析**。
- 答案最多300字，并受原生发送字节上限约束。
- A必须有准确会话标识且不能存在于客户档案。
- B电脑服务与相关接待、发送组件需要运行，未提供云端团队协作。
- 已通过新增合成回归及当次全量670项测试、类型检查和构建；**尚未用真实A/B账号验收收发**。
- 通知会包含客户称呼与部分问题，请仅绑定有权处理该客户资料的销售A。
