# 普通微信后台发送方案评估

核对日期：2026年11月7日。当前用途为非商业比赛中的研究与验证，目标为Windows微信4.1.15.56。后续若用于商业客服、营销或对外销售，需另行核对授权。

“程序后台运行”“微信位于其他窗口后面”“微信始终最小化”和“无需Windows桌面的服务器接口”是不同能力。HTTP或MCP封装本身不能证明发送不依赖前台。

| 路线 | 已核对证据 | 当前判断 |
|---|---|---|

2026年11月7日已完成两项独立固定标记实测：仅向自有单一测试私聊各发送一条，场景分别为微信最小化（minimized），以及窗口未最小化但前台窗口不属于微信进程（测试名occluded，不表示已核验完整物理遮挡）。两项均为sent_verified；新增正数原生消息ID、自发senderUsername、localType=1、时间戳和正文SHA256精确匹配，5ms采样的焦点及最小化状态监控通过。此结果证明本次限定场景的发送与本机落库，不证明对端送达、长期稳定或完整AI接待流程。

本次实验取得并临时加载固定提交9004a6cd98d32ebdcb50f35f15649e6c964e7720的文本DLL，未启动收件Hook、全套机器人、默认回复或防撤回，也未调整系统安全设置。每次调用要求上游success及dll_unloaded，最终独立模块表确认text_bridge.dll与selftest_bridge.dll均未加载。独立实验收尾时，测试授权已撤销，主回复服务running=false、jobs=0，未配置发送适配器；这是该次实验的历史快照。此后产品已加入下述可选组件，默认仍为手动审阅、暂停状态。

## helper的证据与当前最小接入

以下三种证据不能混用：

- **上游声称实测**：[原生说明](https://github.com/Prometheus-first/helper/blob/main/native/README.md)列明4.1.15.56账号发现、文本发送、其他账号发来的群文本、撤回关联及桥接加载与卸载；没有明确列出最小化或其他应用位于前台时的发送实测。
- **源码推断**：[text_service.py](https://github.com/Prometheus-first/helper/blob/main/native/text_service.py#L798)经[run_selftest.py](https://github.com/Prometheus-first/helper/blob/main/native/run_selftest.py#L432)调用DLL导出WxSendText，再由[text_bridge.cpp](https://github.com/Prometheus-first/helper/blob/main/native/text_bridge.cpp#L251)调度微信自身发送任务。这条链不使用模拟键鼠或前台窗口检查，支持“不依赖焦点”的判断；不能替代本机验收。
- **本机证据**：Weixin.dll为204305968字节，SHA256为`e0428a7b691853de496532523c2c09aa095f90941c37c9f4cfb3f137f3c66556`，与上游4.1.15.56条目一致；两次固定标记发送另有上述独立原生记录回读。构建指纹与发送证据分别保存，均不能推出长期稳定。

按[快速开始](https://github.com/Prometheus-first/helper/blob/main/docs/guide/quick-start.md)，上游完整框架运行需要Windows 10/11 x64、64位Python（作者验证3.13）、Microsoft Visual C++ x64运行库，以及requirements.txt中的Python依赖。仓库直接附有text_bridge.dll、selftest_bridge.dll等预编译文件，目前没有GitHub Release。本次最小实验使用隔离Python 3.11.9与pefile 2023.2.7，仅取得并执行145408字节的text_bridge.dll，Git blob SHA与固定提交中的9c0883b67b0a131ec9d95a766c06e378466ce8fd一致；未执行其他桥接DLL。使用已有DLL无需Visual Studio；重新构建才需要MSVC x64工具链，见[构建脚本](https://github.com/Prometheus-first/helper/blob/main/native/build_bridges.ps1)。

客序当前安装器锁定同一提交，创建独立venv并安装pefile，仅在用户主动点击「安装组件」后本机下载所需文本DLL和固定源码。第三方DLL不进入客序源码仓库或本地下载包。当前兼容检查按Windows微信4.1.15.56的精确构建指纹执行，不能仅凭版本号相近放行。

普通文本原生收发不要求第三方机器人平台、模型密钥或云服务。模型与Fish Audio语音属于上游可选功能。上游本机管理台默认监听127.0.0.1:8765，关闭浏览器不停止机器人；启动机器人会加载桥接并建立接收Hook，不能把启动视为纯检查。独立实验和客序当前最小接入均不启动该管理台、NativeTextService接收服务、全套机器人或业务插件。客序启用组件时只读核对当前登录账号，绑定账号、PID及进程创建时间，不启动收件Hook；新消息仍由既有只读导出链读取。账号、会话和正文限制由客序执行，DLL本身仍具有进入整个微信进程的技术能力，并非单会话权限沙箱。

上游现有[HTTP路由](https://github.com/Prometheus-first/helper/blob/main/wxbot_framework/panel_http.py)已提供文本入口，API要求X-Helper-Token，并核对Host及Origin；多账号请求需指定`?robot=对应工作区`。以下接口是框架背景，客序内置原生组件不经该管理台发送。使用上游HTTP接口时，只读取得当前连接后才能提交发送：

| 接口 | 参数或返回含义 |
|---|---|
| GET /api/send-connection | 返回当前session_id；断线或切号后旧连接不可复用 |
| POST /api/send-text | JSON含chat_id、content、request_id、session_id，可选at_list；request_id为16—80位字母、数字、下划线或连字符 |
| GET /api/send-status?id=请求编号 | 查询sending、sent或failed；sent仅反映该发送流程完成 |

[管理台实现](https://github.com/Prometheus-first/helper/blob/main/wxbot_framework/web_panel.py#L753)对相同request_id与相同载荷返回旧任务，冲突载荷拒绝；但只在内存保留最近64条，重启会丢失，不能承担客序的持久幂等。上游Python接入可使用NativeTextBackend与Service的expected_session检查；底层NativeTextService单条限制1023个UTF-8字节，上层Service另有分段能力。客序当前不使用自动拆分：超过1023个UTF-8字节的回复转人工处理。

发送结果需要另做数据库回读。[原生回调](https://github.com/Prometheus-first/helper/blob/main/native/text_bridge.cpp#L131)只检查回调结果首字节并写target、text及completion_success；[Python判断](https://github.com/Prometheus-first/helper/blob/main/native/run_selftest.py#L525)再核对正文、目标和任务清理，没有返回发出消息的native/server message ID，也没有查询微信数据库。管理台消息监控中的bot_generated记录是[SDK合成记录](https://github.com/Prometheus-first/helper/blob/main/wxbot_framework/sdk.py#L81)，不能当作微信落库证据，更不能当作对端送达证据。

客序当前保留账号与唯一chatId路由，显示昵称不参与寻址。每次发送启动独立worker，先核对已绑定账号、PID及进程创建时间，取得发送前数据库游标并以SQLite持久记录幂等请求，再临时加载原生模块执行一次文本发送。要求安全卸载后，通过既有只读数据库链严格核对账号、会话、自发方向、准确正文、正文摘要及新增正数原生消息ID，取得回读凭据后才记为已发送。上游success不能代替这一步。若超时、中断、卸载或回读不确定，结果为unknown，交由人工核对，跨进程或重启后也不自动重发。

使用路径为「自动回复中心 → 原生后台发送 → 安装组件 → 检查状态 → 启用组件」，然后在回复规则中明确选择最多20位真实客户、开启总开关、选择自动模式，保留或调整默认60秒的「等待客户说完」，保存并主动启动。默认仍是手动审阅与暂停，不自动授权全部客户。安装和启用只准备发送能力，不会自动启动接待；停用组件会暂停回复引擎。切换微信账号或重启微信后，需重新检查并启用，旧绑定不能复用。组件配置、幂等数据库及日志保留在本机私有目录，不进入业务导出或Git。

后台及最小化的固定标记可行性已按上述范围验证；内置组件的本机安装及只读账号绑定也已完成真实验证。随后另做一次自有单一测试私聊的联合实测：两条新文本进入同一个任务，默认60秒等待后，AI按已配置商品价格生成回复，经内置组件发送并取得新增原生ID、正文摘要及自发方向严格匹配的回读；发送开始时间不早于等待截止时间，最终仅一个已发送任务。本次以原生验收模式运行，未向模型提供旧聊天历史，结束后已暂停回复。该结果仅覆盖单会话、单批次，不证明对端送达或多客户长期稳定。客户端重连、服务重启、切号停止和长期、多客户无人值守仍需分别验收，详见[完整链路实机验证](自动回复与本机验证.md#单会话完整链路实机验证)。

已有本机视觉发送只支持已校准窗口。临时单会话网关的状态可以区分组件可配置与窗口是否位于前台；这并没有赋予视觉发送器后台输入能力，实际输入与点击仍须前台核验。

若继续使用视觉发送，可考虑在专用Windows电脑或独立虚拟机桌面中运行，让该桌面的微信保持可操作；这属于部署隔离，需要独立验收。当前比赛已取得helper限定发送与一次单会话AI完整链路的证据；将来转向商业使用时，仍须取得明确的当前版本支持与商用授权。
