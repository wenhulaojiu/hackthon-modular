# 自动回复与本机验证

客序提供自动回复中心、商品与服务知识、店铺FAQ、客户白名单、营业时间、回复间隔、转人工规则和持久化任务队列。默认 **手动审阅、后台暂停**，主动启动后读取选定新消息并生成待审核草稿。发送可使用另行安装并启用的内置原生后台组件，也保留外部本机网关。下文记录已完成的自有单会话、单批次完整链路验证；多客户及长期无人值守仍未验收。

## 使用流程

1. 启动客序本地版并完成微信提取组件安装，保持电脑版微信已登录。在「微信数据 → 当前绑定的数据账号」核对绑定；切换数据账号会暂停接待。
2. 在「商品与服务」录入真实产品、价格、服务说明和FAQ。未知价格留空，不依靠模型猜测价格、库存、优惠或承诺。
3. 如需程序发送，在「自动回复中心 → 原生后台发送」点击「安装组件」，完成后「检查状态」并「启用组件」。安装和启用不会自动启动接待，也不选择客户。
4. 在回复规则中明确选择具有准确微信标识的真实好友，设置白名单、营业时段、回复间隔、最长回复及转人工关键词。「等待客户说完」默认60秒，可按需要调整。
5. 先使用「手动审阅」检查草稿；需要自动发送时，确认组件就绪，再开启回复总开关并选择自动模式，点击保存并启动。只有开启总开关而未保存启动，不代表后台已运行。
6. 查看新消息任务与草稿，按需要确认发送、复制、自行发送、拒绝或转人工。缺少就绪的原生组件及其他合格发送网关时，界面不能启动自动发送，后端也会拒绝批准发送。

内置导出器约每30秒轮询选中的最多20位私聊新文本。实际完成时间还取决于本机导出耗时，不能把它描述为即时推送接口。历史文件导入、既有营销待办和启动前历史消息不进入追溯发送流程。示例客户、群聊、文件传输助手、系统通知、非文字、合并转发、引用与支付卡片不应成为自动回复的客户自述证据。

## 等待客户说完与回复间隔

「等待客户说完」默认60秒，可设为0–120整秒；旧规则未保存此项时也按60秒处理。每检测到同一会话一条新的客户文字消息，都会重新计时，把尚未回复的多条消息合并为一次AI生成和一次回复，并保留每条消息的原生标识与原文。重复轮询到同一消息不会延后等待，其他会话独立计时。设为0表示不增加这段等待。

生成中收到补充消息时，旧AI任务会取消或作废，合并后重新等待；旧结果不能发送。退款、改价或人工接管仍会及时阻断未发送回复。已经交给发送适配器的请求无法撤回，后续消息另起一批。

「回复间隔」是上次发送后的冷却限制，与上述等待分别生效；等待结束不表示可以绕过冷却。真实微信读取目前约30秒轮询，实际响应还包含轮询、本机导出和模型耗时，因此默认60秒不代表客户发完后精确60秒收到回复。

白名单只授权处理明确选择的客户；人工接管会停止该客户的自动发送。退款、投诉、改价、明确要求人工、无资料依据或输出不符合规则时转人工处理。消息身份不能唯一确认时停止，而不是凭昵称猜测。

## 页面与后台的关系

后台需要同时满足：微信登录、本地服务在运行、回复服务已主动启动、客户在白名单，以及可用的模型配置和API Key。

启动后台后，关闭浏览器页面不会停止轮询或AI生成。本地进程会继续处理授权范围的新消息，相关上下文、店铺资料和商品知识会发送到配置的模型供应商并产生费用。暂停回复或结束本地服务才会停止处理。单纯导入文件和检查安装状态不会启动这个后台。

队列与去重记录保存在本机私有目录，重启不应重复发送不确定结果。服务重启后需要重新确认运行状态；曾处于发送中的任务会标记结果未知，必须核对微信，不能自动重发。暂停也不能撤回已经被外部网关处理的消息。

## 内置原生后台发送组件

此组件在本地自动回复页提供「安装组件」「检查状态」「启用组件」「停用组件」。默认未安装、未启用，回复规则仍是手动审阅且后台暂停。页面进入时只查询状态；安装与启用都不会替用户选择客户或启动自动回复。

安装器固定helper提交 `9004a6cd98d32ebdcb50f35f15649e6c964e7720`，仅下载锁定的最小源码与文本DLL，并校验文件摘要；创建独立Python虚拟环境，安装 `pefile==2023.2.7`。第三方DLL不包含在源码仓库或本地下载包中，只在用户点击安装后下载到本机。当前仅核验Windows微信 **4.1.15.56** 的精确构建指纹，版本号相同但文件指纹不匹配也不能据此认定兼容。

「检查状态」核对组件与当前环境；「启用组件」只读核对并绑定当前微信账号、PID及进程创建时间，不启动收件Hook、helper管理台、全套机器人或自动接待。接收新消息继续使用客序的只读导出轮询。启用后仍须在回复规则中明确选择最多20位真实私聊客户、开启总开关、选择模式并保存启动。不会默认启用全部客户。换号或重启微信会使旧绑定失效，应重新检查并启用；停用组件会暂停回复引擎。

发送不依赖微信位于前台，可在最小化时调用。每次请求使用独立worker临时加载原生模块，要求安全卸载，再通过只读数据库链核对当前账号、唯一会话、自发方向、新增正数原生消息ID及准确正文摘要；上游返回成功本身不算已发送。当前核验的是本机原生记录，不表示取得对端送达凭证。单条正文上限为 **1023个UTF-8字节**，中文通常占多个字节；超限转人工处理，不自动分段发送。

发送前先将请求编号、目标及正文摘要写入SQLite幂等记录。同一请求不能跨进程再次发送；超时、中断、卸载失败或回读不确定时保留 `unknown`，必须人工核对，不自动重发。组件绑定、SQLite、队列和本机私有运行文件不包含在业务导出中，也不能提交Git或放入下载包。

已在目标电脑真实验证组件安装和当前账号只读绑定，并完成下述自有单会话的完整链路验证；两条独立固定标记另行证明限定窗口场景下的原生发送。当前用途仅为非商业比赛研究；helper许可对商业客服、营销及商业产品集成另有授权要求，商业使用前须取得适用许可。

## 单会话完整链路实机验证

2026年11月7日，在Windows微信4.1.15.56及已绑定的自有单一测试私聊中，完成一次 **两条新文本 → 同一个回复任务 → 默认60秒等待 → AI生成 → 内置原生组件发送 → 严格数据库回读** 的联合实测。任务保留两条消息，AI按已配置商品价格生成回复；发送开始时间不早于该批次的等待截止时间，最终只有一个已发送任务。新增正数原生消息ID、正文摘要和自发方向均与本次发送匹配，证据证明该批次发送并已在本机落库，不等同于取得对端送达凭证。

本次显式开启 `nativeVerificationMode=true`，AI的历史上下文为 `context=[]`，未提供旧聊天历史；本批新消息及已配置店铺、商品资料仍用于生成。此限制属于本次验收模式，不能据此认定日常接待不使用历史上下文。验证结束后已暂停回复；当时保留自动模式、唯一自有测试白名单和60秒等待规则，组件为已启用、就绪状态。规则保留不代表后台仍在运行，也未扩大客户授权。

日常接待在本机组装模型请求时，会省略含疑似密钥的历史消息行，普通上下文照常保留；本批新消息命中长密钥、Bearer token或API Key、Secret Key标签后的长token时，整批在模型请求前停止并转人工，不继续发送。这项过滤不改写原始聊天，也不记录或返回识别出的凭据。

本次结果仅覆盖自有单会话、单批次。多客户并行、更广泛真实客户接待、客户端重连、服务重启后的完整恢复以及长期无人值守仍需分别验收。它与下文的独立固定标记、视觉自测和合成AI测试是不同证据，不能互相扩张范围。原始任务及回读凭据只留在本机私有目录，不公开账号、实际路径、原生ID、摘要值或聊天正文。

## 可选 verified-http 发送网关

除上述内置可选组件外，可选HTTP网关仍可由用户独立准备、取得必要授权并在目标电脑验收，只允许本机回环地址。客序不捆绑第三方微信收发DLL，也不启动第三方自动回复服务器。配置保存在本机私有文件 `.local-wechat/reply-adapter.json`，网页不能设置任意命令或程序路径：

```json
{
  "type": "verified-http",
  "baseUrl": "http://127.0.0.1:你的网关端口",
  "token": "替换为至少16个字符的本机专用凭据"
}
```

这里是结构说明，不是有效端口或真实密钥示例。凭据不应进入页面、业务导出、下载包或Git。

网关健康检查：

```http
GET /kexu/v1/status
```

```json
{
  "protocol": "kexu-reply-v1",
  "ready": true,
  "capabilities": {
    "stableChatIds": true,
    "readback": true,
    "idempotentSend": true
  }
}
```

发送请求：

```http
POST /kexu/v1/send
Content-Type: application/json
```

```json
{
  "chatId": "选定客户的稳定会话ID",
  "text": "经审核或规则通过的回复正文",
  "idempotencyKey": "该持久化任务的唯一幂等标识"
}
```

只有网关返回与请求匹配、经过真实目标会话回读的完整凭证，任务才可成为 `sent`：

```json
{
  "status": "sent",
  "chatId": "与请求相同的会话ID",
  "messageId": "微信回读得到的真实消息ID",
  "textSha256": "发送正文UTF-8字节的SHA256摘要",
  "readback": true
}
```

仅HTTP成功、按钮点击成功、任意`success:true`、本地生成的假消息ID或与正文不匹配的摘要，都不是这份凭证。超时、中断、回执缺失或不匹配时标记 `unknown` 并转人工，不自动重试，以免重复回复。幂等标识也不能代替实际发送后回读。

缺少就绪的原生组件及其他合格网关时，手动审阅仍可生成和复制草稿，自动发送启动与批准发送必须被拒绝。已配置原生组件但停用或核验失败时不会自动回退HTTP网关。完成该协议的接入测试也不等于已在所有微信版本完成真实发送验收。

## 临时单会话测试网关

`scoped-test-http` 仅供操作者明确授权后，人工绑定自己的一个测试号及当前前台微信窗口。它依靠本次局部视觉校准和指定会话回读，授权最多5分钟、最多3次发送尝试；切换账号、窗口变化、过期或配额用完均须停止。它没有通用稳定客户会话识别能力，不能用于多客户或长期无人值守发送，也不能代替 `verified-http` 的通用能力验收。

此处说明的是临时测试边界，不表示真实客户自动回复已经实测通过。只有实际收件、模型生成、发送及目标会话数据库回读证据全部匹配，才可对该次受限测试作出结论。

## 独立原生后台发送验证

2026年11月7日，在Windows微信4.1.15.56上使用固定提交9004a6cd98d32ebdcb50f35f15649e6c964e7720的helper文本桥接完成两项独立测试。145408字节DLL的Git blob SHA与固定提交匹配；最小运行环境为隔离Python 3.11.9与pefile 2023.2.7。仅向自有单一测试私聊各发送一条固定标记，不接入AI、不启动收件Hook、全套机器人、默认自动回复或防撤回。

两项场景为：微信最小化（minimized），以及窗口未最小化但前台窗口不属于微信进程（测试名occluded，不表示已核验完整物理遮挡）。两项均为sent_verified，5ms采样的焦点及最小化状态监控通过；本机新增正数原生消息ID、自发senderUsername、localType=1、时间戳及正文SHA256均精确匹配。此处核验的是本机原生记录，不表示已取得对端送达凭证。

每次调用同时要求上游success与dll_unloaded，最终独立模块表确认text_bridge.dll及selftest_bridge.dll均未加载。该独立实验结束时的快照为：测试授权已撤销，主回复服务running=false、jobs=0，未配置发送适配器。这是当时的实验收尾状态。此后产品接入可选原生组件，完成安装、只读绑定及上文单会话单批次的完整链路实测；长期、多客户无人值守仍未验收。测试器的单会话约束也不等于原生DLL只具有单会话权限。方案与授权边界见[后台发送方案评估](后台发送方案评估.md)。

## 文件传输助手自测原型

`scripts/local-wechat/selftest-sender.py` 是独立实验脚本，不是客户发送网关。它只生成固定格式的唯一短自测标记，拒绝客户会话与任意正文，不会让自动回复页获得发送能力。默认运行仅输出依赖信息，不连接微信。

视觉实验模式 `visual-filehelper-only` 使用独立Python环境及可选的 `scripts/local-wechat/requirements-sender-visual.txt`，并复用既有只读导出环境。操作者须确认界面账号、系统文件传输助手和空输入区；程序使用本机 `zh-Hans` OCR、系统助手图标及当前窗口校准复核目标。只读取所需局部像素，不抓取全屏，不外传截图或OCR内容。数据工作区标识不能证明界面登录账号。

固定自测标记通过剪贴板单次粘贴，会覆盖当前剪贴板；粘贴后还须逐字OCR一致才点击一次发送。脚本在编辑前持久化发送中状态，再从filehelper记录核对新增正数原生消息标识、商家发送方向和正文摘要；正文不符、超时、歧义或崩溃均不能标记成功，也不自动重发。原UIA路径因没有可用控件仍拒绝发送，视觉实验没有替它补齐稳定客户会话身份。

2026年11月7日，Windows 微信4.1.15.56上的一次固定标记程序发送已取得严格数据库回读凭证，结果为 `sent / READBACK_CONFIRMED`；同一自测请求另起CLI进程执行返回 `duplicate: true`，未重复发送。23项Python合成测试通过。此结果只证明该次文件传输助手自测，未注册生产客户发送网关，也不会启用客户自动发送；不代表所有客户或长期无人值守发送通过。

## 第三方项目边界

参考项目 [Weix](https://github.com/zqaini002/weix) 当前自有部分声明仅供非商业使用，客序不复制其实现、不捆绑其程序、不自动启动其服务。商用集成需要另行获得适用授权。

Weix现有HTTP发送接口返回的成功不能直接视为本协议的精确会话数据库回读凭证；现有消息接口也不能可靠还原所有私聊消息方向。因此它不是默认即可接通的 verified-http 网关。不同微信版本、权限和第三方组件许可需分别确认，不把其他设备的成功记录当作本机验证。
