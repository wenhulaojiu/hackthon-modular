# 自动回复与本机验证

客序提供自动回复中心、商品与服务知识、店铺基础信息、首次添加欢迎语、指定客户范围、自动接待新私聊、营业时间、回复间隔、转人工规则和持久化任务队列。默认 **手动审阅、后台暂停**，主动启动后读取授权范围的新消息并生成待审核草稿。发送可使用另行安装并启用的内置原生后台组件，也保留外部本机网关。下文分别记录自有单会话单批次实测，以及2026年11月7日一位真实新增测试好友的自动建档、固定欢迎和按当时60秒配置等待后的价格咨询回复的发送回读验证；500客户规模、多客户及长期无人值守仍未验收。

## 使用流程

1. 启动客序本地版并完成微信提取组件安装，保持电脑版微信已登录。在「微信数据 → 当前绑定的数据账号」核对绑定；切换数据账号会暂停接待。
2. 在「商品与服务」录入产品、价格、库存和服务说明，在「店铺基础信息」填写联系人、电话、地址、服务内容、营业时段及「首次添加欢迎语」。商品说明可写明口味、规格、原料、过敏原、保存条件和保质期；未知资料留空，不依靠模型猜测。比赛试用可先加载下文的虚拟店铺资料，食品期限属于样例设定。
3. 如需程序发送，在「自动回复中心 → 原生后台发送」点击「安装组件」，完成后「检查状态」并「启用组件」。安装和启用不会自动启动接待，也不选择客户。
4. 在回复规则中选择具有准确微信标识的真实好友，或开启「自动接待新私聊」；设置营业时段、回复间隔、最长回复及转人工关键词。页面顶部「回复等待时间」默认10秒，可独立保存秒数或分钟数。
5. 先使用「手动审阅」检查草稿；需要自动发送时，确认组件就绪，再开启回复总开关并选择自动模式，点击保存并启动。只有开启总开关而未保存启动，不代表后台已运行。
6. 查看新消息任务与草稿，按需要确认发送、复制、自行发送、拒绝或转人工。缺少就绪的原生组件及其他合格发送网关时，界面不能启动自动发送，后端也会拒绝批准发送。

工作区档案和接待授权最多500位；该容量不等于每轮全量导出500个会话。收件已接入只读会话水位探针，每轮已选客户与未知私聊共用一次元数据进程；只返回最新消息水位，不返回正文，无水位变化就不导出正文，同秒新消息ID也能识别。已选会话中的商户新消息仍会触发人工接管。SQLite合成协议测试和一位真实新测试好友的欢迎、价格咨询收发已通过，尚未完成500客户规模实机性能验收。调度约每30秒检查一次，实际完成时间还取决于探针、本机导出与模型耗时，不能描述为即时推送或已经通过500人并发实测。

历史文件导入、既有营销待办和启动前历史消息不进入追溯发送流程。示例客户、群聊、文件传输助手、系统通知、非文字、合并转发、引用与支付卡片不应成为自动回复的客户自述证据。

## 等待客户说完与回复间隔

页面顶部的「回复等待时间」默认10秒，支持秒／分钟输入、0–3600整数秒（最多60分钟），以及10秒、30秒、1分钟、2分钟、5分钟快捷选项。分钟可含小数，但换算后必须为整数秒，例如1.5分钟=90秒；接口秒数为负数、小数、`null`、字符串或大于3600时拒绝。旧规则未保存此项时也按10秒处理。每检测到同一会话一条新的客户文字消息，都会重新计时，把尚未回复的多条消息合并为一次AI生成和一次回复，并保留每条消息的原生标识与原文。重复轮询到同一消息不会延后等待，其他会话独立计时。设为0表示不增加这段等待。

「保存等待时间」只更新已保存规则中的等待项，其他未提交的规则草稿保留。保存等待时间或完整规则会暂停接待，之后仍需用户主动重新启动；从完整规则页保存也不会回写旧的等待值。

生成中收到补充消息时，旧AI任务会取消或作废，合并后重新等待；旧结果不能发送。退款、改价或人工接管仍会及时阻断未发送回复。已经交给发送适配器的请求无法撤回，后续消息另起一批。

「回复间隔」是上次发送后的冷却限制，与上述等待分别生效；等待结束不表示可以绕过冷却。真实微信读取目前约30秒轮询，实际响应还包含轮询、本机导出和模型耗时，因此默认10秒不代表客户发完后精确10秒收到回复。

指定客户范围只授权处理已选客户；另行开启的「自动接待新私聊」按下节规则增量接纳新客户。人工接管会停止该客户的自动发送。退款、投诉、改价、明确要求人工、无资料依据或输出不符合规则时转人工处理。消息身份不能唯一确认时停止，而不是凭昵称猜测。

普通咨询缺少口味、保质期等资料时，模型可返回资料不足澄清，由服务端使用固定文案告知需要与店员核实，不采用模型编造的细节。AI将本条问题交给人工处理时，不再自动把整个客户会话永久锁定，后续普通咨询可继续处理。敏感规则、商家明确点击接管、检测到微信内商家人工回复及发送异常仍保留会话保护；已有接管记录不会被升级过程自动清空。

## 在处理队列中手动回复

在真实客户的处理卡片中直接填写文字，点击「发送到微信」。该操作使用当前工作区已安装、启用并就绪的原生后台组件，自动接待暂停时也可进行，不启动收件或扩大自动接待范围。手动发送会保持该客户处于人工接管；需要交还AI时再点击「恢复托管」。云端页面和虚拟客户不能实际发送。

每条人工回复最多300个字符、1023个UTF-8字节。后端根据原任务和当前持久化客户资料确认唯一真实会话，页面不能另外指定微信收件人。请求先持久化幂等编号，再使用单次会话授权发送并严格回读；重复点击、断线重查或重启不会自动重复发送。只有取得准确正文、原生消息标识和当前账号匹配的回读结果，页面才显示已核实发送；失败保留文字，结果未知时须先核对微信。

## 最近对话与回应意图

当前默认等待为10秒；已明确保存的自定等待仍按保存值执行。普通消息先结合最近客户和商户对话判断回答（answer，发送结果使用 `reply`）、忽略（ignore）或澄清（clarify），退款等情况仍可转人工。纯标点、确认、致谢和招呼不自动等于商品咨询，不会因为商品库有价格就任意挑选商品报价；只有最近真实对话能唯一确定省略对象时才承接回答，商品或需求指代不明则先澄清。

发送适配器返回已核实的 `sent` 后，正文立即写入该会话的商户上下文；后续轮询读到同一原生消息的延迟回声时去重，避免遗漏刚刚说过的话、重复写入或误判人工接管。欢迎后120秒内的纯标点和简单招呼会被记录但不额外生成AI回复，也不重置已经在等待的实质问题；包含商品、价格或其他具体需求的消息仍应正常处理。语境、回声防重和欢迎保护已通过合成回归，尚未二轮真实发送复测。

## 新私聊自动建档与批量导入

「自动接待新私聊」默认勾选，但总开关默认关闭、后台默认暂停。主动保存并启动后，尚未建档的有效好友私聊出现本次启动后的明确好友添加系统提示，或首次带来启动后的真实客户新文本时，先按稳定微信标识幂等建立「新客户」档案并保存，再将新档案加入接待范围。可以在现有客户选择为空时启动新私聊接待；不会扫描历史好友补发欢迎语。

微信会话目录不能可靠证明何时添加好友。程序只识别受支持的完整好友添加系统句式，并核对原生系统消息类型和方向；普通聊天中复述同一句话不算添加事件。没有可识别提示时，只能在该新客户首条咨询时欢迎一次，不能据此声称准确识别了添加时刻。旧会话中的历史消息、只有昵称的新目录条目、群聊、公众号、系统账号及商户自己发出的消息都不能触发自动建档接待。已有档案未选中、已关闭自动回复或已人工接管时，不会借新消息自动重新开启。

追加新客户不通过完整规则保存／重新启动，不改变其他客户已有等待截止、生成租约或人工接管；原生授权在已开始的发送安全结束后再扩展。追加期间如果发生暂停、换号或规则变化，会停止接纳，不会自动恢复接待。新客户继续使用当前等待时间、营业时段、审阅／自动模式和转人工规则，不会绕过它们。达到500位档案或业务状态容量时停止并保留已有数据。

「微信数据」页只有「一键提取」「导入记录」「导出记录」。提取名单可以全选当前筛选结果，筛选外已选联系人保留；多于20位时按每批最多20位串行提取，每批验证、保存成功再继续。失败、取消或离开页面停止后续批次，已保存批次保留，余下联系人可重试；尚未结束的本机任务应先继续检查或取消。日期范围最多连续31天，仍受500位客户、每位1500条、全体12000条及完整状态字节上限限制。历史导入只整理档案，不启动回复，也不追溯发送。

「导出记录」显示工作台发起的下载，不能证明浏览器已完成存盘或文件仍存在。默认跟进间隔位于「客户跟进」页，可保存1–365整数天；跟进待办日期不会自行触发微信发送。

## 跟进卡的一键跟进

「客户跟进」每张卡提供「一键跟进」，点击即由商户批准发送当前已保存的话术，不会现场调用AI重新生成。需要先生成或编辑并保存，且话术为有效的300字符以内文本，同时受1023个UTF-8字节发送上限限制。操作要求本机回复服务正在运行、总开关开启、组件可发送，客户为唯一可确认的真实私聊，已在当前授权范围且启用回复、未人工接管，并满足营业时段和冷却规则。按钮不会代为启动服务、加入客户或扩大授权范围。

程序按已有私聊队列顺序发送并记录任务幂等标记。只有获得本条跟进已核实的 `sent` 回执及原生消息凭据，且任务编号、客户和已保存正文相符，才由发送流程标记完成；排队、请求受理或结果未知都不算完成。后续点击只检查原任务，不重复提交；`unknown` 必须人工核对，不自动重发。修改已提交话术不能变成同一任务的再次发送，需要另建跟进任务。

跟进页移除任务类型筛选，只保留待处理、已完成、全部记录。该页隐藏客户名末尾「（演示）」仅改变显示文字，`source=demo` 仍保留，演示客户继续禁止发送。到期日期不会自行发消息。本轮一键跟进与显示调整只有合成验证，未进行真实跟进发送。

## 首次添加欢迎语

入口为「商品与服务 → 店铺基础信息 → 首次添加欢迎语」。欢迎开关默认开启，文案最多300字符；回复总开关仍默认关闭，服务仍保持暂停。可直接编辑，也可点击「根据店铺信息生成」，只用已填店名、服务内容、完整电话、地址及已启用的有效营业时段拼成文案，不调用AI、不自动保存或发送。启用欢迎语且内容为空白时不能保存；关闭后可明确保存空串，程序不会悄悄换回默认文案。

识别到本次启动后的明确添加好友提示时，为新接纳客户安排一次欢迎；没有可识别提示时，在该新客户首条咨询时安排一次。欢迎正文直接使用已保存文案，不等待普通咨询的合并计时，也不调用AI；同一客户先处理欢迎，随后咨询仍按当前默认10秒或自定等待处理。欢迎任务及一次性标记会持久保存，重复轮询、两种触发先后出现或重启不会再创建第二条欢迎，不向启动前历史好友补发。

实际发送要求本机接待已主动启动，客户接待权限、总开关、发送组件、营业时段与冷却规则均满足。手动审阅模式只生成待审阅欢迎语，须商户批准后才能发送；非营业时间的欢迎保留排队，到营业时段且后台仍运行时再处理。暂停、人工接管或规则失效会阻止发送，结果未知仍转人工，不自动重试。保存文案不代表已经开始接待。

## 比赛演示店铺

入口为「AI 与设置 → 数据管理 → 比赛演示店铺 → 加载演示店铺」。如有未保存的设置，先完成保存。加载会先暂停本机接待，建立「青禾生活馆」、30位虚拟客户、16项商品、6项服务、90笔虚拟销售、4笔虚拟退款及18项演示待办；可用于查看客户画像、商品价格和经营页面。所有演示交易只代表虚拟样例，不能视为实际收入。

加载保留真实客户、真实交易和任务、原有非演示商品、导入导出记录及模型配置和已保存API Key；店名、行业、店铺基础信息、首次欢迎语及营业时段设置会改为演示资料。演示文案说明这是比赛店铺，地址明确虚构；演示时段写为每日09:00–21:00，自动回复时段限制默认关闭，需要限制时请在店铺基础信息启用。重复加载按演示来源替换旧虚拟资料，真实记录即使ID带有 `competition-` 前缀也会保留，新增ID会避开已有真实ID。加入资料后仍受500客户、200商品、5000订单、5000任务、12000聊天及1450000个UTF-8字节上限限制，超限拒绝，不删减真实资料腾空间。

30位演示客户均为 `source=demo`，关闭自动回复且不加入接待范围，不会向其发送消息。加载按钮不会启动回复。需要用自有新好友试用时，应核对当前微信数据账号、商品及欢迎文案，在自动回复中心检查组件、选择模式，保留「自动接待新私聊」，再主动保存并启动。演示构造、保存与防重已有合成回归；一位真实新增测试好友已完成自动建档、固定欢迎发送、按当时60秒配置等待后的美式咖啡价格咨询回复及原生回读，范围见下节实测记录。

## 页面与后台的关系

后台需要同时满足：微信登录、本地服务在运行、回复服务已主动启动、客户在指定范围或已通过新私聊增量接纳，以及可用的模型配置和API Key。

启动后台后，关闭浏览器页面不会停止轮询或AI生成。本地进程会继续处理授权范围的新消息，相关上下文、店铺资料和商品知识会发送到配置的模型供应商并产生费用。暂停回复或结束本地服务才会停止处理。单纯导入文件和检查安装状态不会启动这个后台。

队列与去重记录保存在本机私有目录，重启不应重复发送不确定结果。服务重启后需要重新确认运行状态；曾处于发送中的任务会标记结果未知，必须核对微信，不能自动重发。暂停也不能撤回已经被外部网关处理的消息。

手机可在浏览器访问[既有私有云站](https://merchant-hub-oyr-1107.oo2592575661.chatgpt.site)，用具有访问权限的同一ChatGPT账号登录。云端与本地D1各自保存数据；手机云页不会直接读取本机微信，也不会自动同步当前本地档案、聊天或队列，不能代替本机接待进程。实际收发仍要求电脑版微信和客序本地服务持续运行。`127.0.0.1` 是当前设备自身地址，手机无法用它访问电脑本地版。

## 内置原生后台发送组件

此组件在本地自动回复页提供「安装组件」「检查状态」「启用组件」「停用组件」。默认未安装、未启用，回复规则仍是手动审阅且后台暂停。页面进入时只查询状态；安装与启用都不会替用户选择客户或启动自动回复。

安装器固定helper提交 `9004a6cd98d32ebdcb50f35f15649e6c964e7720`，仅下载锁定的最小源码与文本DLL，并校验文件摘要；创建独立Python虚拟环境，安装 `pefile==2023.2.7`。第三方DLL不包含在源码仓库或本地下载包中，只在用户点击安装后下载到本机。当前仅核验Windows微信 **4.1.15.56** 的精确构建指纹，版本号相同但文件指纹不匹配也不能据此认定兼容。

「检查状态」核对组件与当前环境；「启用组件」只读核对并绑定当前微信账号、PID及进程创建时间，不启动收件Hook、helper管理台、全套机器人或自动接待。接收新消息继续使用客序的只读读取链路。启用后仍须在回复规则中选择真实私聊客户或保留「自动接待新私聊」，开启总开关、选择模式并保存启动，接待范围最多500位。组件启用本身不会授权全部已有联系人。换号或重启微信会使旧绑定失效，应重新检查并启用；停用组件会暂停回复引擎。

发送不依赖微信位于前台，可在最小化时调用。每次请求使用独立worker临时加载原生模块，要求安全卸载，再通过只读数据库链核对当前账号、唯一会话、自发方向、新增正数原生消息ID及准确正文摘要；上游返回成功本身不算已发送。当前核验的是本机原生记录，不表示取得对端送达凭证。单条正文上限为 **1023个UTF-8字节**，中文通常占多个字节；超限转人工处理，不自动分段发送。

发送前先将请求编号、目标及正文摘要写入SQLite幂等记录。同一请求不能跨进程再次发送；超时、中断、卸载失败或回读不确定时保留 `unknown`，必须人工核对，不自动重发。组件绑定、SQLite、队列和本机私有运行文件不包含在业务导出中，也不能提交Git或放入下载包。

已在目标电脑真实验证组件安装和当前账号只读绑定，并完成下述自有单会话的完整链路验证；两条独立固定标记另行证明限定窗口场景下的原生发送。当前用途仅为非商业比赛研究；helper许可对商业客服、营销及商业产品集成另有授权要求，商业使用前须取得适用许可。

## 可选 verified-http 发送网关

除上述内置可选组件外，可选HTTP网关仍可由用户独立准备、取得必要授权并在目标电脑验收，只允许本机回环地址。客序不捆绑第三方微信收发DLL，也不启动第三方自动回复服务器。配置保存在本机私有文件 `.local-wechat/reply-adapter.json`，网页不能设置任意命令或程序路径：

```json
  "baseUrl": "http://127.0.0.1:你的网关端口",

}
```

这里是结构说明，不是有效端口或真实密钥示例。凭据不应进入页面、业务导出、下载包或Git。

网关健康检查：

```http
GET /kexu/v1/status
```

```json
{
  "protocol": "kexu-reply-v1",
  "ready": true,
  "capabilities": {
    "stableChatIds": true,
    "readback": true,
    "idempotentSend": true
  }
}
```

发送请求：

```http
POST /kexu/v1/send
Content-Type: application/json
```

```json
{
  "chatId": "选定客户的稳定会话ID",
  "text": "经审核或规则通过的回复正文",
  "idempotencyKey": "该持久化任务的唯一幂等标识"
}
```

只有网关返回与请求匹配、经过真实目标会话回读的完整凭证，任务才可成为 `sent`：

```json

  "status": "sent",
  "chatId": "与请求相同的会话ID",
  "messageId": "微信回读得到的真实消息ID",
  "textSha256": "发送正文UTF-8字节的SHA256摘要",

}
```

仅HTTP成功、按钮点击成功、任意`success:true`、本地生成的假消息ID或与正文不匹配的摘要，都不是这份凭证。超时、中断、回执缺失或不匹配时标记 `unknown` 并转人工，不自动重试，以免重复回复。幂等标识也不能代替实际发送后回读。

缺少就绪的原生组件及其他合格网关时，手动审阅仍可生成和复制草稿，自动发送启动与批准发送必须被拒绝。已配置原生组件但停用或核验失败时不会自动回退HTTP网关。完成该协议的接入测试也不等于已在所有微信版本完成真实发送验收。

## 文件传输助手自测原型

`scripts/local-wechat/selftest-sender.py` 是独立实验脚本，不是客户发送网关。它只生成固定格式的唯一短自测标记，拒绝客户会话与任意正文，不会让自动回复页获得发送能力。默认运行仅输出依赖信息，不连接微信。

视觉实验模式 `visual-filehelper-only` 使用独立Python环境及可选的 `scripts/local-wechat/requirements-sender-visual.txt`，并复用既有只读导出环境。操作者须确认界面账号、系统文件传输助手和空输入区；程序使用本机 `zh-Hans` OCR、系统助手图标及当前窗口校准复核目标。只读取所需局部像素，不抓取全屏，不外传截图或OCR内容。数据工作区标识不能证明界面登录账号。

固定自测标记通过剪贴板单次粘贴，会覆盖当前剪贴板；粘贴后还须逐字OCR一致才点击一次发送。脚本在编辑前持久化发送中状态，再从filehelper记录核对新增正数原生消息标识、商家发送方向和正文摘要；正文不符、超时、歧义或崩溃均不能标记成功，也不自动重发。原UIA路径因没有可用控件仍拒绝发送，视觉实验没有替它补齐稳定客户会话身份。

2026年11月7日，Windows 微信4.1.15.56上的一次固定标记程序发送已取得严格数据库回读凭证，结果为 `sent / READBACK_CONFIRMED`；同一自测请求另起CLI进程执行返回 `duplicate: true`，未重复发送。23项Python合成测试通过。此结果只证明该次文件传输助手自测，未注册生产客户发送网关，也不会启用客户自动发送；不代表所有客户或长期无人值守发送通过。
