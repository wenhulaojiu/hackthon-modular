# 自动回复与本机验证

客序提供自动回复中心、商品与服务知识、店铺FAQ、客户白名单、营业时间、回复间隔、转人工规则和持久化任务队列。默认运行方式是 **读取选定新消息并生成待审核草稿**。发送能力由单独的本机网关提供，默认没有配置；功能界面存在不等于微信自动发送已完成实机验收。

## 使用流程

1. 启动客序本地版并完成微信提取组件安装，保持电脑版微信已登录。在「微信数据 → 当前绑定的数据账号」核对绑定；切换数据账号会暂停接待，需重新启动。
2. 在「商品与服务」录入真实产品、价格、服务说明和FAQ。未知价格留空，不依靠模型猜测价格、库存、优惠或承诺。
3. 在「自动回复中心」选择具有准确微信标识的真实好友，设置白名单、营业时段、间隔、最长回复及转人工关键词。
4. 先使用「手动审阅」模式，保存规则，再主动启动本机服务。开启总开关但没有保存并启动，不代表已经运行。
5. 查看新消息任务与草稿，按需要复制、自行发送、拒绝或转人工。缺少发送网关时，界面不能启动自动发送，后端也会拒绝批准发送。

内置导出器约每30秒轮询选中的最多20位私聊新文本。实际完成时间还取决于本机导出耗时，不能把它描述为即时推送接口。历史文件导入、既有营销待办和启动前历史消息不进入追溯发送流程。示例客户、群聊、文件传输助手、系统通知、非文字、合并转发、引用与支付卡片不应成为自动回复的客户自述证据。

白名单只授权处理明确选择的客户；人工接管会停止该客户的自动发送。退款、投诉、改价、明确要求人工、无资料依据或输出不符合规则时转人工处理。消息身份不能唯一确认时停止，而不是凭昵称猜测。

## 页面与后台的关系

后台需要同时满足：微信登录、本地服务在运行、回复服务已主动启动、客户在白名单，以及可用的模型配置和API Key。

启动后台后，关闭浏览器页面不会停止轮询或AI生成。本地进程会继续处理授权范围的新消息，相关上下文、店铺资料和商品知识会发送到配置的模型供应商并产生费用。暂停回复或结束本地服务才会停止处理。单纯导入文件和检查安装状态不会启动这个后台。

队列与去重记录保存在本机私有目录，重启不应重复发送不确定结果。服务重启后需要重新确认运行状态；曾处于发送中的任务会标记结果未知，必须核对微信，不能自动重发。暂停也不能撤回已经被外部网关处理的消息。

## 可选 verified-http 发送网关

客序不捆绑微信收发SDK，也不启动第三方自动回复服务器。可选网关必须由用户独立准备、具备必要授权并在目标电脑验收，只允许本机回环地址。配置保存在本机私有文件 `.local-wechat/reply-adapter.json`，网页不能设置任意命令或程序路径：

```json
{
  "type": "verified-http",
  "baseUrl": "http://127.0.0.1:你的网关端口",
  "token": "替换为至少16个字符的本机专用凭据"
}
```

这里是结构说明，不是有效端口或真实密钥示例。凭据不应进入页面、业务导出、下载包或Git。

网关健康检查：

```http
GET /kexu/v1/status
```

```json
{
  "protocol": "kexu-reply-v1",
  "ready": true,
  "capabilities": {
    "stableChatIds": true,
    "readback": true,
    "idempotentSend": true
  }
}
```

发送请求：

```http
POST /kexu/v1/send
Content-Type: application/json
```

```json
{
  "chatId": "选定客户的稳定会话ID",
  "text": "经审核或规则通过的回复正文",
  "idempotencyKey": "该持久化任务的唯一幂等标识"
}
```

只有网关返回与请求匹配、经过真实目标会话回读的完整凭证，任务才可成为 `sent`：

```json
{
  "status": "sent",
  "chatId": "与请求相同的会话ID",
  "messageId": "微信回读得到的真实消息ID",
  "textSha256": "发送正文UTF-8字节的SHA256摘要",
  "readback": true
}
```

仅HTTP成功、按钮点击成功、任意`success:true`、本地生成的假消息ID或与正文不匹配的摘要，都不是这份凭证。超时、中断、回执缺失或不匹配时标记 `unknown` 并转人工，不自动重试，以免重复回复。幂等标识也不能代替实际发送后回读。

默认缺少合格网关时，手动审阅仍可生成和复制草稿，自动发送启动与批准发送必须被拒绝。完成该协议的接入测试也不等于已在所有微信版本完成真实发送验收。

## 文件传输助手自测原型

`scripts/local-wechat/selftest-sender.py` 是独立实验脚本，不是客户发送网关。它只生成固定格式的唯一短自测标记，拒绝客户会话与任意正文，不会让自动回复页获得发送能力。默认运行仅输出依赖信息，不连接微信。

视觉实验模式 `visual-filehelper-only` 使用独立Python环境及可选的 `scripts/local-wechat/requirements-sender-visual.txt`，并复用既有只读导出环境。操作者须确认界面账号、系统文件传输助手和空输入区；程序使用本机 `zh-Hans` OCR、系统助手图标及当前窗口校准复核目标。只读取所需局部像素，不抓取全屏，不外传截图或OCR内容。数据工作区标识不能证明界面登录账号。

固定自测标记通过剪贴板单次粘贴，会覆盖当前剪贴板；粘贴后还须逐字OCR一致才点击一次发送。脚本在编辑前持久化发送中状态，再从filehelper记录核对新增正数原生消息标识、商家发送方向和正文摘要；正文不符、超时、歧义或崩溃均不能标记成功，也不自动重发。原UIA路径因没有可用控件仍拒绝发送，视觉实验没有替它补齐稳定客户会话身份。

2026年11月7日，Windows 微信4.1.15.56上的一次固定标记程序发送已取得严格数据库回读凭证，结果为 `sent / READBACK_CONFIRMED`；同一自测请求另起CLI进程执行返回 `duplicate: true`，未重复发送。23项Python合成测试通过。此结果只证明该次文件传输助手自测，未注册生产客户发送网关，自动回复页的客户自动发送仍禁用；不代表所有客户或长期无人值守发送通过。

## 第三方项目边界

参考项目 [Weix](https://github.com/zqaini002/weix) 当前自有部分声明仅供非商业使用，客序不复制其实现、不捆绑其程序、不自动启动其服务。商用集成需要另行获得适用授权。

Weix现有HTTP发送接口返回的成功不能直接视为本协议的精确会话数据库回读凭证；现有消息接口也不能可靠还原所有私聊消息方向。因此它不是默认即可接通的 verified-http 网关。不同微信版本、权限和第三方组件许可需分别确认，不把其他设备的成功记录当作本机验证。

## 已确认的本机验证摘要

| 项目 | 已确认结果 |
|---|---|
| 系统与客户端 | Windows，微信4.1.15.56 |
| Python | 64位3.11.9，支持`sqlite3.deserialize` |
| 导出组件 | 固定公开提交安装成功，使用独立依赖环境 |
| 真实读取范围 | 仅文件传输助手自测消息，不含客户会话 |
| 初次只读验证 | 手工发送后回读1条自测消息，格式、验证报告及文件摘要通过 |
| 独立程序发送 | 视觉模式单次固定标记发送，新增原生消息、发送方向及正文摘要严格匹配 |
| 跨进程幂等 | 同一请求另起CLI进程返回重复请求，未重发 |
| 数据处理 | 没有公开聊天正文、账号、实际路径或密钥，没有上传或导入业务数据库 |

上述新增发送证据只覆盖人工确认后的系统文件传输助手，不覆盖真实客户接待、生产发送网关或长期无人值守。客户自动发送继续禁用。完整真实测试摘要与产物只保留在本机忽略目录，不进入公开文档、源码或下载包。

2026年11月7日的独立AI复验已通过：本机Workerd经Node传输桥和本机代理调用官方OpenAI的 `gpt-4.1-mini`，连接、合成客户画像、营销草稿、消费候选、门店资料约束客服回复及退款转人工6项全部通过。验证只使用合成客户与合成知识，临时条目与规则已按版本检查清理，消费候选没有自动记账，没有调用微信发送。此结果证明模型链路可用，不能代替客户发送网关和完整接待流程的实机验收。

安装器的回归测试只使用合成ZIP和伪造路径，检查真实商店版Python识别、中文源码解包、路径越界、符号链接、重复文件、覆盖和容量限制；不扫描微信、不读取私聊或密钥。
