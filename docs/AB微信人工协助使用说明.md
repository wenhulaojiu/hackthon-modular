# A/B微信人工协助（本地版）

本次已接入项目实际代码，不只是架构设计。A为销售私人微信，B为对客个人微信，系统接入B，无需第三个助手号。

## 使用

1. Windows电脑登录B，启动最新客序本地版，安装并启用既有原生后台发送组件。
2. 让A和B成为好友。进入「自动回复」页面的「A/B微信人工协助」，填写A准确的会话标识（wxid，不是昵称），点击启用。A不得存在于客户档案。
3. 配置接待范围、知识资料和规则，保存并启动接待。人工协助只转交启用之后产生的新转人工问题，不补发历史队列。
4. 客户向B发来需要人工的问题后，B向A发送客户称呼、部分问题内容及唯一编号。该客户暂时进入人工保护。
5. 销售使用A，在与B的聊天框发送普通文字：`#完整问题编号 您的答案`。示例：`#12345678-1234-1234-1234-123456789abc 请携带购物凭证到店，我们为您核实处理。`
6. 系统严格匹配A身份和原工单，再复用现有单次人工发送接口，由B发往原客户。页面展示通知、待答、发送及异常状态。

首版必须明确编号，不解析微信引用卡片或转发卡片；正文最多300字且不超过原生发送字节限制。问题通知是普通文字摘要，不是原生转发卡片。不要把这两点误认为引用解析已实现。

## 运行边界

- 默认关闭。启用通知意味着会把客户称呼和部分问题发送给绑定A。
- B电脑、本地服务、接待后台与原生发送组件需可用；A直接使用普通微信。
- 每个本地微信工作区独立保存配置与问题记录，不包含云端团队同步、小程序或多销售权限体系。
- A从新私聊自动接纳中排除，并禁止放入客户接待配置，避免循环。
- 已通知问题不会重复通知；状态先持久化再派发。通知或答案发送结果未知不自动重试，重启不重发中断的发送。
- 新问题、手工回复或原任务取消等使旧答案不再适用时，转人工复核。自动恢复托管仍沿用既有人工发送恢复保护，不无条件解除。
- 停用会取消未回答问题，已派发发送无法撤回。更换A先停用再启用。错误配置、通知失败或匹配失败请在原有人工接管界面处理。

## 验证范围

新增合成回归覆盖编号解析、准确路由、伪造发送者拒绝、历史消息排除、并发防重、重启未知结果保留、停用取消与新消息复核。未用真实微信账号做A/B收发验收，不能宣称真实环境已验证。
