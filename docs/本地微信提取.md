# 客序本地版与微信提取

本地版把工作台、客户资料、聊天和本地 D1 数据库存放在当前电脑。手动 AI 在点击时调用模型；主动启用本机回复后台后，指定客户和「自动接待新私聊」范围内的新消息也可能触发模型请求。默认手动审阅且后台暂停，可选原生后台发送组件需要另行安装、检查并启用；项目不会自动确认营业收入。后台与发送说明见 [自动回复与本机验证](自动回复与本机验证.md)。

## 开始使用

1. 安装包含 npm 的 Node.js 24 或更新版本。将下载包完整解压到自己的可写目录，不要直接在 ZIP 中运行。
2. 双击 `启动客序.cmd`。首次启动会安装项目依赖、创建本地应用加密配置、构建运行配置，并按项目 Drizzle 日志初始化本地数据库；后续复用已准备的内容。
3. 服务确认就绪后只打开 `http://127.0.0.1:5173/`。保留启动窗口，使用 Ctrl+C 停止本次服务。5173已被占用时会停止，不会打开或连接不相关程序，也不会自动改用其他端口。
4. 需要普通微信提取时，再单独双击 `安装微信提取组件.cmd`。它只准备公开源码和独立 Python 依赖，**不扫描微信、不读取消息、不生成密钥**。
5. 保持 Windows 微信已登录，在本地工作台中选择好友私聊与时间范围，再主动点击提取。首次使用前核对账户和联系人；重名时使用准确的会话标识，不静默选择第一个。

首次依赖安装和下载需要网络。安装失败时保留窗口和日志，根据错误处理后重试；不要重复执行建表SQL或删除整个数据库来绕过错误。

## 比赛演示店铺与首次欢迎

在「AI 与设置 → 数据管理 → 比赛演示店铺」点击「加载演示店铺」，可加载「青禾生活馆」、30位虚拟客户、16项商品、6项服务及虚拟经营记录。加载会暂停接待，保留真实客户、交易、任务、原有非演示商品和模型配置、API Key；店名、行业、店铺基础信息、欢迎语和营业时段设置会改为演示资料。重复加载替换旧演示，超出工作区容量时拒绝，不删除真实资料腾空间。演示交易不是实际收入，30位演示客户均关闭自动回复且排除接待范围，加载本身不启动或发送。

「商品与服务 → 店铺基础信息 → 首次添加欢迎语」可编辑最多300字符的欢迎内容，或根据已填写店铺资料本地生成。生成不调用模型、不自动保存发送；欢迎开关默认开启，但回复总开关默认关闭、服务暂停。启用且留空不能保存；停用后明确保存空串不会被默认文案覆盖。首次欢迎触发、营业时间和审阅规则见[首次添加欢迎语](自动回复与本机验证.md#首次添加欢迎语)。2026年11月7日，一位真实新增测试好友已完成自动建档、固定欢迎发送及按当时60秒配置等待后的美式咖啡18元价格回复，两条均有原生回读；500人规模及长期接待仍未验收。

## 选择与批量提取

「微信数据」仅保留「一键提取」「导入记录」「导出记录」。点击「读取微信会话」后，可搜索联系人并使用「全选当前结果」「取消全选当前结果」，筛选外已选联系人会保留；「清空全部」会取消所有当前选择。导入记录显示已经保存的提取结果，导出记录显示已经发起的业务文件下载。

全选超过20人时自动按每批最多20位串行提取，当前批通过验证并保存成功后才继续下一批；每批会重新核对会话。失败、取消或离开页面会停止后续批次，已经保存的批次保留；尚未结束的原任务应先继续检查或取消，避免重复创建任务。剩余选择会保留供重试，刷新后仍须重新读取并核验会话。

每次日期范围最多连续31天。工作区最多500位客户、每位最多1500条聊天、全体最多12000条、单条最多8000字；完整业务状态前端上限为1450000个UTF-8字节，服务端保存上限为1500000字节。即使名单可以全选，也可能先触及消息或状态容量；超限会停止后续批次，不自动删除旧数据腾出空间。

## 微信与 Python 环境

提取组件使用用户指定的 [yeklongdi/wechat-chat-export](https://github.com/yeklongdi/wechat-chat-export)，固定提交 `d82f241e88e9357dc3a553c958ef516605bb85be`。上游声明支持 Windows 微信4.x，并核对过4.1.6.46的会话目录。本项目已在4.1.15.56完成文件传输助手自测消息的只读回读，字段、验证报告和摘要校验通过；另完成独立Python脚本的一次固定标记发送和严格回读，边界见下文。未公开账号、实际路径、消息或密钥，不同客户端、进程权限或数据库格式受限时仍会如实报错。

需要已安装的64位 Python 3.11或更新的3.x版本，并支持 `sqlite3.deserialize`。安装器先检查明确指定的解释器，再尝试 `py` 启动器和 PATH，只排除 WindowsApps 根目录的启动占位程序；商店包目录内真实解释器在版本和功能验证通过后可以使用，本机已确认Python3.11.9可用。找不到可用解释器时会提示你自行安装，不会安装系统 Python、改系统设置、自动提权或关闭防护。

安装器在 `.local-wechat/venv` 创建隔离环境，按上游 `requirements.txt` 安装锁定版本依赖，不向系统 Python 安装包。默认源码只进入 `.local-wechat/tools/`，已有未登记内容不会覆盖。解包使用Python标准库，不依赖PowerShell Archive模块，并拒绝越界路径、符号链接、重复路径及超出大小/数量限制的包。下载包、安装失败的暂存和日志保留在 `.local-wechat/`，不上传到云端。

## 复用已配置环境

可在自己的 PowerShell 中设置以下环境变量，再运行相应 CMD。这里仅为路径示意，请替换为自己的实际绝对路径，不要把真实账户路径和配置文件公开分享：

```powershell
$env:KEXU_EXPORTER_ROOT = 'D:\Tools\wechat-chat-export'
$env:KEXU_PYTHON = 'C:\Python311\python.exe'
$env:KEXU_WECHAT_DB_DIR = 'D:\WeChatData\xwechat_files\本人已选账户\db_storage'
& '.\安装微信提取组件.cmd'
```

`KEXU_EXPORTER_ROOT` 指包含 `SKILL.md`、`scripts/export_wechat.py` 和 `requirements.txt` 的已审核工具根目录。显式复用的源码版本由你管理，安装器不覆盖或自动更新它。`KEXU_PYTHON` 选择用于创建隔离环境的现有解释器；真正运行路径写为隔离环境的 `python.exe`。首次安装可通过 `KEXU_WECHAT_DB_DIR` 指定本人已选择的 `db_storage`；已有账号登记后，使用页面中的账号选择切换，不直接修改路径。

安装成功后仅在 `.local-wechat/config.json` 保存：

```json
{
  "exporterRoot": "工具源码绝对路径",
  "pythonPath": "本项目隔离环境Python绝对路径",
  "dbDir": "可选：已选账号db_storage绝对目录"
}
```

没有 `dbDir` 时由上游尝试定位；检测到多个账户时应先明确选择。网页不能修改命令或解释器路径。此配置不含数据库密钥，安装器也不调用vendor的 `extract`、`decrypt`、调试捕获或密钥写出命令。

## 切换微信数据账号

电脑版微信换号不会自动更改已绑定的数据目录。在「微信数据 → 当前绑定的数据账号」选择对应目录尾号，点击「切换数据账号」。目录存在只表示本机保留了该号的数据，不代表该号现在已登录；程序不按目录修改时间猜测账号。

首次更新保留原绑定为原有工作区。新账号使用独立客户、消费、任务、导入记录、商品资料与接待队列，初始不包含示例客户；门店与模型设置沿用，API Key共用服务端加密存储。切回原账号可继续使用原资料。切换会暂停接待、取消读取任务并刷新页面；旧页面和迟到请求不能把结果写入另一个账号。使用原生发送时，切号或重启微信后应重新检查、启用组件，核对登录账号和白名单后再主动启动接待；旧账号或旧进程的绑定不能继续发送。

账号登记保存在 `.local-wechat/accounts.json`。外部直接修改 `config.json` 的账号路径会触发绑定不一致并拒绝读取，应回到页面重新选择账号；不要删除登记文件来绕过检查。

## 本机模型网络

OpenAI可在「AI 与设置」选择自定义兼容接口，Base URL填 `https://api.openai.com/v1`，例如模型 `gpt-4.1-mini`；API Key填Secret Key，Tracking ID不填。程序会追加 `/chat/completions`。

本地模式通过受内部随机凭证保护的Node传输桥请求公共HTTPS模型接口，保持证书校验并拒绝所有跳转；云端继续使用托管运行环境联网。若电脑直连不通，可在私有文件 `.local-wechat/network.json` 配置已经运行的本机HTTP代理：

```json
{"httpsProxy":"http://127.0.0.1:7890"}
```

端口需与自己的代理软件一致；此设置不更改系统代理、证书或安全设置。只允许无用户名密码的本机回环代理。`{"httpsProxy":""}` 显式使用直连；没有文件时读取进程的HTTPS_PROXY。网络检查状态会说明当前传输方式，API Key不发送给浏览器或写入此文件。

## 业务数据导出

在「微信数据 → 导出记录」点击「导出数据」，可选择全数据JSON、客户CSV、消费CSV或跟进CSV。全数据JSON包含当前门店的聊天、画像、消费退款、任务、商品服务资料与回复规则，不含模型API Key；三个CSV分别下载，使用UTF-8 BOM，便于表格软件读取中文。

客户消费次数只统计已确认销售，已确认退款扣减净额；待确认和已排除记录不计净额或消费次数。导出只读取当前记录，不会确认交易或修改状态。

导出记录只证明工作台已发起浏览器下载，不能证明浏览器已完成保存，也不记录最终存盘路径。请在浏览器下载列表或本机文件夹核对文件；记录中的客户数和消息数是发起时的快照。

当前没有完整JSON备份的导入还原界面，因此它是业务资料导出，不能称为一键恢复。JSON也不包含本机发送器凭据、数据库密钥或后台运行队列文件；不要将全数据JSON误放进聊天导入入口。导出中含客户与聊天资料，保留在受控位置，不提交Git或公开分享。

手机可打开[现有私有云站](https://merchant-hub-oyr-1107.oo2592575661.chatgpt.site)，使用具有访问权限的同一ChatGPT账号登录。云站和本地版各自存储数据，手机不会通过云站直接读取电脑微信，也不会自动看到当前本地客户、聊天或回复队列；手机上的 `127.0.0.1` 指手机自身。电脑微信和客序本地服务仍需持续运行，才能实际读取与发送，手机云页不会替代本机后台。

## 本机回复后台

在商品与服务知识、FAQ、指定客户和回复规则准备好之后，主动保存并启动本机回复服务。接待范围最多500位真实私聊客户；「自动接待新私聊」开启时也可暂不选择现有客户，只等待启动后的有效新入站消息。默认手动审阅且暂停，启动后只拟草稿，商户可审阅、拒绝、复制或接管客户；未安装并启用原生组件且未配置其他合格适配器时，不能启动自动发送，批准发送也会被拒绝。

自动回复页顶部的「回复等待时间」默认10秒，可独立保存0–3600整数秒，也可切换为分钟输入（最多60分钟，换算后必须为整数秒，例如1.5分钟=90秒），并提供10秒、30秒、1分钟、2分钟、5分钟快捷选项。0表示不增加这段等待；旧配置缺少该项时也默认10秒。接口秒数为负数、小数、`null`、字符串或大于3600时均会拒绝。每检测到同一会话的新客户文字消息都会重置等待，将全部尚未回复的消息合并生成一次回复，保留逐条原生标识和原文；重复消息不重置，跨会话独立。生成中又收到消息，会废弃旧AI结果并重新合并等待；退款、改价和接管仍会阻断未发送回复，已交给发送适配器的请求无法撤回。

单独保存等待时间只修改此项，其他未提交的规则草稿保留，并暂停接待；调整等待时间或完整规则后，仍需用户主动重新启动。

该等待与「回复间隔」分别生效：前者等待这一轮连续输入结束，后者限制上次发送后的冷却时间，设等待为0也不能绕过冷却。实际响应还包含约30秒轮询、本机导出和模型耗时，不承诺发完消息后精确10秒回复。

回复结合最近客户与商户对话判断回答（answer）、忽略（ignore）或澄清（clarify）；没有具体咨询不任意报价，商品或需求指代不清时先询问。核实 `sent` 后立即把已发正文写入商户上下文，后续相同原生消息的延迟回声去重。欢迎后120秒内简单招呼或纯标点不额外调用AI、不重置实质问题的等待，具体咨询仍正常处理。上述语境与欢迎保护已有合成回归，尚未二轮实发复测。

「自动接待新私聊」默认勾选，只有在回复总开关已开启且主动保存启动后才工作。尚未建档的有效好友私聊出现本次启动后的明确添加好友系统提示，或首次带来真实入站新文本时，先按稳定微信标识幂等建立「新客户」并加入回复范围。欢迎语在可识别添加提示后安排一次；没有可识别提示时，在该新客户首条咨询时欢迎一次。目录中新出现昵称并不证明添加时刻，不能单独触发；不向历史好友补发。已存在但未选中、已禁用或人工接管的客户不会被自动重新开启；群聊、公众号、系统账号和启动前历史消息排除。

欢迎使用已保存文案，不调用AI或等待普通咨询的合并计时；后续咨询仍按当前等待规则处理。欢迎任务与一次性标记持久保存，重复提示、首条咨询和重启不会重复创建。手动审阅模式只生成待审阅欢迎；营业时段限制和冷却仍生效，非营业时间的欢迎保留排队。实际发送仍需后台运行和有效发送权限，`unknown` 结果转人工且不自动重发。

500是客户档案和授权范围上限，不表示每轮全量导出500人的聊天。只读会话水位探针已接入：每轮已选客户与未知私聊共用一次元数据进程，返回会话水位而不返回正文，仅为有变化的私聊按需导出正文，同秒新消息ID也能识别；已选会话中的商户新消息仍触发人工接管。SQLite合成协议测试已通过，一位真实新测试好友的建档、欢迎与价格咨询已完成发送回读；500客户规模实机性能和并发接待仍未验收。演示构造、全选分批及时间配置边界继续使用合成回归。

该次新好友实测使用当时的60秒配置，并发现欢迎后单个句号会触发AI再次介绍；当前默认等待已改为10秒，欢迎120秒保护与最近对话语境修复已通过合成回归，尚未二轮实发复测。已通过范围和待复测项见[真实新好友验证](自动回复与本机验证.md#真实新好友欢迎与价格咨询验证)。

「默认跟进间隔」在「客户跟进」页设置，范围1–365整数天；具体客户的跟进日期在档案中单独调整。站内跟进日期不会直接触发微信营销发送。

跟进卡的「一键跟进」直接批准发送当前已保存话术。仅在Windows本地版回复服务已运行、组件就绪、真实客户在当前既有授权范围且启用回复、未接管时可用，并沿用营业时间和冷却限制；不会自动启动服务或扩展授权。只有本条任务取得正文一致的已核实 `sent` 原生回执，才由发送流程完成任务；重复点击只查询原任务，`unknown` 不自动重发。该功能仅做合成验证，未实际发送跟进消息。跟进页移除任务类型筛选、隐藏客户名末尾「（演示）」只影响显示，虚拟来源仍保留且禁发。

微信需保持登录、本地服务需保持运行，并配置有效AI Key。后台模式下可以关闭浏览器页面，处理仍由本地进程继续；关闭启动窗口或暂停回复后停止处理。启用前应明确这一持续读取和模型调用范围。

可选 `scoped-test-http` 只限人工明确绑定自己的一个测试号和当前前台窗口，授权最多5分钟、最多3次发送尝试；它不是多客户通用发送网关，不代表真实客户自动回复或长期无人值守已验证。范围、窗口或授权失效即停止，完整边界见[临时单会话测试网关](自动回复与本机验证.md#临时单会话测试网关)。

## 可选原生后台发送

微信提取组件负责只读导出；原生后台发送是另行准备的可选组件。在「自动回复中心 → 原生后台发送」依次点击「安装组件」「检查状态」「启用组件」。安装器固定helper提交 `9004a6cd98d32ebdcb50f35f15649e6c964e7720`，下载所需文本DLL并创建独立Python环境，安装 `pefile==2023.2.7`；第三方DLL不随源码或本地下载包分发，只在用户点击安装后下载到本机。

当前仅核验Windows微信4.1.15.56的精确客户端指纹。启用时只读核对当前账号与进程创建时间，不启动收件Hook、第三方机器人或接待。若要自动发送，再在回复规则中选择真实客户或保留「自动接待新私聊」，开启总开关、选择自动模式，保留或调整默认10秒等待，保存并启动。组件启用本身不会授权所有已有联系人，也不会发送主动营销消息。

组件就绪后无需微信保持前台，也可最小化。每次发送由独立worker临时加载原生模块，确认安全卸载后，通过只读导出链严格核对新增原生消息、账号、会话、发送方向与正文摘要；SQLite记录持久幂等，结果未知 `unknown` 时转人工且不自动重发。正文超过1023个UTF-8字节转人工处理，不自动拆分。停用组件会暂停回复；换号或重启微信后需重新检查并启用。

已真实验证组件安装与账号只读绑定，并完成自有单一测试私聊的单批次完整链路：两条新文本合并成一个任务，当时配置的60秒等待结束后，AI按已配置商品价格生成一条回复，经内置组件发送并取得严格原生回读。本次使用验收模式，未向模型提供旧聊天历史；结束后已暂停回复。该结果不代表多客户或长期无人值守已验收。当前组件只用于非商业比赛研究；商业客服、营销或产品集成需另获适用授权。详细证据见[完整链路实机验证](自动回复与本机验证.md#单会话完整链路实机验证)。

## 当前边界

- 只读取当前电脑已保存且有权访问的记录，不保证包含手机或其他电脑历史。
- 本工作台仅接收好友私聊，群聊和文件传输助手不归到某一位客户；图片、语音、视频只保留类型和已有描述。
- 合并转发、引用与支付卡片不能作为客户本人事实或营业收入凭证；消费、退款必须有可核对证据并由商家确认。
- 启动和组件安装都不自动提取微信；用户主动发起提取或启动白名单回复后台后，才运行指定范围的导出。
- 当前发送实机证据包括文件传输助手固定标记及跨进程防重、两个窗口场景的独立原生标记、自有单会话两条新文本合并后按当时60秒配置等待的AI完整链路，以及一位新增测试好友的固定欢迎和按当时60秒配置等待后的18元价格回复。后者两条均取得原生回读，不能扩大为500客户规模或长期验收。更广泛客户接待、多个客户并行及长期无人值守仍未验收；纯标点二次介绍的修复尚未二轮实发复测。公开自动化回归使用合成数据，不放入真实聊天或密钥。

## 文件传输助手独立视觉自测

独立实验CLI使用可选的 `scripts/local-wechat/requirements-sender-visual.txt` 和单独Python环境。2026年11月7日在Windows 微信4.1.15.56上，经人工确认系统文件传输助手与空输入区，本机中文OCR和局部窗口校准通过后，程序完成一次固定标记发送；数据库回读的原生消息、发送方向和正文摘要严格一致，同一请求另起进程未重复发送。

固定标记经剪贴板单次粘贴，**会覆盖当前剪贴板**；发送前逐字OCR核对正文，不抓取全屏、不外传截图或OCR内容。原UIA模式因没有可用控件仍拒绝发送。该文件传输助手实验不注册客户发送网关，不接受任意客户或正文，也不会启用客户自动发送。完整边界见[自动回复与本机验证](自动回复与本机验证.md#文件传输助手自测原型)。

## 开发者打包

```powershell
node scripts/package-local.mjs
```

生成 `public/kexu-local.zip`。包中只放运行所需源码、锁文件、入口和文档，排除依赖、构建产物、数据库、环境变量、密钥、日志、Git信息和本机工具。ZIP属于构建产物，不应提交源码仓库；`.env.example` 可作为无真实凭据的示例保留。

如不希望自动打开浏览器，可设置 `KEXU_NO_BROWSER=1` 后运行启动器，再手动访问显示的本机地址。
